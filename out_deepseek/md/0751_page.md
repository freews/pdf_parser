<|ref|>text<|/ref|><|det|>[[114, 89, 883, 134]]<|/det|>
**DH Value Length (DHVLEN):** Diffie-Hellman exponential length. This length shall be a multiple of 4. If the DH group identifier is cleared to 0h (i.e., NULL DH exchange), this field shall be cleared to 0h. Otherwise, it shall be set to the length in bytes of the DH Value.

<|ref|>text<|/ref|><|det|>[[114, 142, 883, 185]]<|/det|>
**Sequence Number (SEQNUM):** 32-bit sequence number S1. A random non-zero value shall be used as the initial value. The sequence number is incremented modulo \(2^{32}\) after each use, except that the value 0h is skipped (i.e., incrementing the value FFFFFFFFh results in the value 00000001h).

<|ref|>text<|/ref|><|det|>[[114, 193, 883, 279]]<|/det|>
**Challenge Value (CVAL):** Shall be set to a random challenge value C1 (refer to section 8.3.5.5.7). Each challenge value should be unique and unpredictable, since repetition of a challenge value in conjunction with the same key may reveal information about the key or the correct response to this challenge. The algorithm for generating the challenge value is outside the scope of this specification. Randomness of the challenge value is crucial to the security of the protocol (refer to section 8.3.5.5.7). The CVAL length is the same as the length of the selected hash function (i.e., HL).

<|ref|>text<|/ref|><|det|>[[114, 287, 883, 345]]<|/det|>
**DH Value (DHV):** Diffie-Hellman exponential. If the DH Value Length is cleared to 0h, this field is not present. The DH value shall be set to the value of \(g^{*}\) mod p, where x is a random number selected by the controller that shall be at least 256 bits long (refer to section 8.3.5.5.7) and p and g shall have the values indicated in Figure 799, based on the selected DH group identifier.

<|ref|>text<|/ref|><|det|>[[114, 352, 550, 366]]<|/det|>
Upon receiving a DH-HMAC-CHAP_Challenge message, if:

<|ref|>text<|/ref|><|det|>[[143, 376, 883, 404]]<|/det|>
·the Hash Length (HL) does not match the value specified in Figure 798 for the selected hash function;

<|ref|>text<|/ref|><|det|>[[143, 407, 548, 420]]<|/det|>
·the Sequence Number (SEQNUM) is cleared to 0h;

<|ref|>text<|/ref|><|det|>[[143, 422, 883, 464]]<|/det|>
·DHgID is cleared to 0h and the AUTH_Negotiate message (refer to section 8.3.5.4.1) that the host sent for this instance of the DH-HMAC-CHAP protocol requested secure channel concatenation (i.e., the SC_C field in that message is set to a non-zero value);

<|ref|>text<|/ref|><|det|>[[143, 466, 721, 480]]<|/det|>
·DHgID is non-zero and the DH Value Length (DHVLEN) is cleared to 0h; or

<|ref|>text<|/ref|><|det|>[[143, 482, 600, 495]]<|/det|>
·DHgID is non-zero and the DH Value (DHV) is 0, 1, or p-1;

<|ref|>text<|/ref|><|det|>[[114, 504, 257, 516]]<|/det|>
then the host shall:

<|ref|>text<|/ref|><|det|>[[143, 526, 883, 554]]<|/det|>

# 8.3.5.5.4 DH-HMAC-CHAP_Reply Message

<|ref|>text<|/ref|><|det|>[[114, 605, 883, 661]]<|/det|>
The DH-HMAC-CHAP_Reply message is sent from the host to the controller. The host may request authentication of the controller to enable bidirectional authentication, by including a DH-HMAC-CHAP challenge value C2 in this message. The challenge value C2 shall be different from the challenge value C1 received in the DH-HMAC-CHAP_Challenge message.
