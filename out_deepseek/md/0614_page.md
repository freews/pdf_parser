#### 8.1.18.4 Runtime D3 (RTD3) Transitions (PCle only)  

<|ref|>text<|/ref|><|det|>[[114, 310, 881, 341]]<|/det|>
In Runtime D3, main power is removed from the controller. Auxiliary power may or may not be provided. RTD3 is used for additional power savings when the controller is expected to be idle for a period of time.  

<|ref|>text<|/ref|><|det|>[[114, 346, 882, 407]]<|/det|>
In this specification, RTD3 refers to the \(\mathsf{D3}_{\mathsf{cold}}\) power state described in the PCI Express Base Specification. RTD3 does not include the PCI Express \(\mathsf{D3}_{\mathsf{hot}}\) power state because main power is not removed from the controller in the \(\mathsf{D3}_{\mathsf{hot}}\) power state. Refer to the PCI Express Base Specification for details on the \(\mathsf{D3}_{\mathsf{hot}}\) power state and the \(\mathsf{D3}_{\mathsf{cold}}\) power state.  

<|ref|>text<|/ref|><|det|>[[114, 412, 882, 472]]<|/det|>
To enable the host to determine when to use RTD3, the controller reports the RTD3 Entry Latency (RTD3E) field and the RTD3 Resume Latency (RTD3R) field in the Identify Controller data structure in Figure 328. The host may use the sum of these two values to evaluate whether the expected idle period is long enough to benefit from a transition to RTD3.  

<|ref|>text<|/ref|><|det|>[[114, 478, 882, 509]]<|/det|>
The RTD3 Resume Latency is the expected elapsed time from the time power is applied until the controller is able to:  

<|ref|>text<|/ref|><|det|>[[142, 514, 882, 560]]<|/det|>
a) process and complete I/O commands; and 
b) access the resources (e.g., formatted storage) associated with attached namespace(s), if any, as part of I/O command processing.  

<|ref|>text<|/ref|><|det|>[[114, 565, 882, 610]]<|/det|>
The latency reported is based on a normal shutdown with optimal controller settings preceding the RTD3 resume. The latency reported assumes that the host enables and initializes the controller and sends a 4 KiB read operation.  

<|ref|>text<|/ref|><|det|>[[114, 616, 882, 662]]<|/det|>
If CSTS.ST is cleared to '0', then the RTD3 Entry Latency is the expected elapsed time from the time CC.SHN is set to 01b by the host until CSTS.SHST is set to 10b by the controller. When CSTS.SHST is set to 10b, the controller is ready for the host to remove power.

#### 8.1.18.5 Host Controlled Thermal Management  

<|ref|>text<|/ref|><|det|>[[114, 695, 882, 799]]<|/det|>
A controller may support host controlled thermal management (HCTM), as indicated in the Host Controlled Thermal Management Attributes of the Identify Controller data structure in Figure 328. Host controlled thermal management provides a mechanism for the host to configure a controller to automatically transition between active power states or perform vendor specific thermal management actions in order to attempt to meet thermal management requirements specified by the host. If active power states transitions are used to attempt to meet these thermal management requirements specified by the host, then those active power states transitions are vendor specific.  

<|ref|>text<|/ref|><|det|>[[114, 804, 882, 878]]<|/det|>
The host specifies and enables the thermal management requirements by setting the Thermal Management Temperature 1 field and/or Thermal Management Temperature 2 field (refer to section 5.2.26.1.9) in a Set Features command to a non- zero value. The supported range of values for the Thermal Management Temperature 1 field and Thermal Management Temperature 2 field are indicated in the Identify Controller data structure in Figure 328.
