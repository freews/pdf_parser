<|ref|>text<|/ref|><|det|>[[114, 89, 690, 105]]<|/det|>
If an NVM Set is deleted, then the following actions are performed in sequence:  

<|ref|>text<|/ref|><|det|>[[144, 111, 590, 126]]<|/det|>
1) the NVM Set Identifier is removed from the NVM Set List;  

<|ref|>text<|/ref|><|det|>[[142, 126, 883, 156]]<|/det|>
2) if the Media Unit Status log page is supported, then the NVM Set Identifier field is cleared to Oh in all Media Unit Status Descriptors, if any, that indicated the deleted NVM Set;  

<|ref|>text<|/ref|><|det|>[[144, 156, 502, 170]]<|/det|>
3) for each namespace in the deleted NVM Set:  

<|ref|>text<|/ref|><|det|>[[200, 177, 883, 257]]<|/det|>
a. all commands targeting the namespace are handled as described for namespace deletion in section 8.1.16; 
b. the namespace identifier is removed from the Allocated Namespace ID list; 
c. the namespace is deleted; 
d. for each controller to which the namespace was attached when that namespace was deleted:  

<|ref|>text<|/ref|><|det|>[[263, 272, 883, 331]]<|/det|>
i. the namespace identifier is added to the Changed Attached Namespace List log page for that controller; and 
ii. an Attached Namespace Attribute Changed asynchronous event is generated by that controller as described in section 8.1.16.2;  

<|ref|>text<|/ref|><|det|>[[200, 336, 883, 366]]<|/det|>
e. the namespace identifier is added to the Changed Allocated Namespace List log page for each controller in the NVM subsystem; and  

<|ref|>text<|/ref|><|det|>[[200, 366, 883, 410]]<|/det|>
f. an Allocated Namespace Attribute Changed asynchronous event is generated for each controller that has Allocated Namespace Attribute Notices enabled as described in section 8.1.16.2;  

<|ref|>text<|/ref|><|det|>[[173, 410, 204, 423]]<|/det|>
and  

<|ref|>text<|/ref|><|det|>[[142, 431, 883, 462]]<|/det|>
4) the Unallocated Endurance Group Capacity indicated by the Endurance Group Information log page is increased by the amount of capacity formerly allocated to the NVM Set.  

<|ref|>text<|/ref|><|det|>[[114, 468, 883, 498]]<|/det|>
If any of the entities modified by the above sequence are accessed after the sequence begins and before it completes, then the results are indeterminate.  

<|ref|>text<|/ref|><|det|>[[114, 504, 881, 535]]<|/det|>
If an NVM Set is created or deleted, the value indicated by the Unallocated NVM Capacity (UNVMCAP) field of the Identify Controller data structure is not changed.  

<|ref|>title<|/ref|><|det|>[[115, 543, 408, 559]]<|/det|>
#### 8.1.4.2 Fixed Capacity Management  

<|ref|>text<|/ref|><|det|>[[114, 568, 883, 627]]<|/det|>
A Media Unit represents a component of the underlying media in a domain. An implementation may choose to represent each die as a separate Media Unit; however, this is not required. A Media Unit is the smallest media component for which the controller reports wear information (refer to the Available Spare field and the Percentage Used field in the Media Unit Status Descriptor, Figure 260).  

<|ref|>text<|/ref|><|det|>[[114, 634, 881, 665]]<|/det|>
Two or more I/O operations to a Media Unit at the same time may interfere with each other as they contend for resources internal to or shared by that Media Unit.  

<|ref|>text<|/ref|><|det|>[[114, 670, 498, 686]]<|/det|>
A controller supporting Fixed Capacity Management:  

<|ref|>text<|/ref|><|det|>[[142, 692, 883, 810]]<|/det|>
a) shall support the Media Unit Status log page (refer to section 5.2.12.1.16); 
b) shall support Endurance Groups (refer to section 3.2.3); 
c) may support NVM Sets (refer to section 3.2.2); 
d) shall set the Fixed Capacity Management bit to '1' in the CTRATT field of the Identify Controller data structure (refer to Figure 328); 
e) shall support the Supported Capacity Configuration List log page (refer to section 5.2.12.1.17); and 
f) shall support the Select Capacity Configuration operation of the Capacity Management command (refer to section 5.2.3).  

<|ref|>text<|/ref|><|det|>[[114, 817, 883, 861]]<|/det|>
Media Units are accessed by way of Channels that represent communication pathways that may be a source of contention. This information is reported to facilitate the composition of NVM Sets that minimize interference between independent writers competing for this type of resource.
