#### 3.1.4 Controller Properties  

<|ref|>text<|/ref|><|det|>[[114, 425, 883, 485]]<|/det|>
A property is a dword, or qword attribute of a controller. The attribute may have read, write, or read/write access. The host shall access a property using the width specified for that property with an offset that is at the beginning of the property unless otherwise noted in a transport specific specification. All reserved properties and all reserved bits within properties are read- only and return Oh when read.  

<|ref|>text<|/ref|><|det|>[[114, 491, 883, 522]]<|/det|>
For message- based controllers, properties may be read with the Property Get command and may be written with the Property Set command.  

<|ref|>text<|/ref|><|det|>[[114, 528, 883, 560]]<|/det|>
For memory- based controllers, refer to the applicable NVMe Transport binding specification for access methods and rules (e.g., NVMe over PCIe Transport Specification).  

<|ref|>text<|/ref|><|det|>[[114, 565, 883, 597]]<|/det|>
Figure 33 and Figure 34 describe the property map for a memory- based controller. Figure 33 and Figure 35 describe the property map for a message- based controller.  

<|ref|>text<|/ref|><|det|>[[114, 602, 674, 619]]<|/det|>
Accesses that target any portion of two or more properties are not supported.  

<|ref|>text<|/ref|><|det|>[[115, 624, 452, 640]]<|/det|>
Software should not rely on Oh being returned.
